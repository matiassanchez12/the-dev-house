## Approaches — per locked decision, does it fit?

1. **`illustration_path` nullable column + card fade / per-category gradient+icon fallback** — FITS. Column style matches (`difficulty` is the sibling nullable string). Card already accepts a leading `<img>` child (`Card` CSS `has-[>img:first-child]:pt-0`). Effort: Low.

2. **Media disk + DB path + `StorageUrlHelper`** — FITS exactly (`PhaseService`/phase-image precedent, `ApiResourceTransformer::project()` image mapping). `projectIdeas()` transformer already does per-field mapping so `illustrationUrl` is a one-line add. Effort: Low.

3. **Source images at `database/seeders/assets/project-ideas/<slug>.webp`, seeder copies idempotently, missing→null** — FITS with a caveat. Use a **deterministic destination path** (`project-ideas/<slug>.webp` on the media disk) so re-running the seeder yields byte-identical `illustration_path` values (upsert stays idempotent) and re-copy is a safe overwrite (or skip-if-exists). Seeder must read the source with `file_get_contents(database_path(...))` NOT `Storage` (the asset lives in the repo tree, not on the disk), then `Storage::disk($disk)->put(...)`. This works under `Storage::fake('public')`. Effort: Medium (new file-IO branch + test).

4. **`idea_slug` on the form; `StoreProjectRequest` `nullable|string|exists`; `ProjectService::create` copies illustration to `projects/` as `images[0]` only when uploads empty; uploads always win; no `cover_path` column** — FITS. Insertion point is clean (right after `uploadImages`, before `createdProjects()->create`). Copy target `projects/<uuid>.<ext>` keeps `isSafeImagePath` happy for later deletes. Effort: Medium.

5. **Theme-aware fade with guaranteed contrast; gradient+icon maps in `project-idea-catalog.ts`** — FITS but needs care. Repo is Tailwind v4 with `.dark` class + semantic oklch tokens; **use semantic tokens + a real scrim, not `dark:` overrides and not a thin low-opacity gradient** (per follow-card contrast history). Recommended: overlay `bg-gradient-to-t from-background via-background/70 to-background/30` (adapts to light/dark automatically because `--background` flips) OR a solid `bg-background/60` + `backdrop-blur-[1px]`. Text/badges sit on the CardHeader area BELOW the image, not on top of it — simplest guaranteed contrast: image is a **separate fixed-aspect block above the header**, header keeps `bg-card`/`text-card-foreground`. The fade then only needs to blend the image's bottom edge into the card, not carry text. Effort: Low-Medium.

6. **English identifiers/comments, Spanish user copy** — matches existing files. Effort: none.

### Idea-card layout consistency (folded-in scope)
- **Layout today**: `project-idea-category-group.tsx` renders `<ul className="grid grid-cols-1 gap-3 sm:grid-cols-2 lg:grid-cols-3">`, each idea in `<li key={idea.slug}>` → `<ProjectIdeaCard className="h-full">`.
- **Why heights leak**: CSS Grid default `align-items: stretch` makes every `<li>` in a row take that row's max height, and `Card h-full` fills the `<li>`. So *within one row* cards are already equal height — the visible imbalance is that **one long `summary` (col is `string(500)`) inflates its entire row**, leaving large blank gaps in the 2 sibling cards, while the next row is short. Optional bits (difficulty badge present/absent, 1 vs 2 lines of tech badges) add smaller wobble.
- **`h-full` today**: it DOES get a bounded height (grid stretch resolves the `<li>` height), so `h-full` already works — it just fills a height that varies per row.
- **Fix to spec**:
  - Clamp `CardDescription` to `line-clamp-2` (or `-3`); add `title={idea.summary}` so the full sentence is still available on hover; the full scope also lives in `prefillDescription`.
  - Illustration/fallback region must be a **fixed-aspect block** (`aspect-video` / `aspect-[16/9]`, `overflow-hidden`), never `h-auto` on an `<img>` — so it contributes constant height whether image, gradient, or icon.
  - Keep card structure identical regardless of optional difficulty badge / tech count: give `CardContent` `flex-1` and consider reserving the difficulty row (render an empty-height-stable slot) or accept minor variance; clamp the tech `<ul>` to one line with `overflow-hidden` + `+N` overflow badge (mirrors `ProjectCardTechs` `overflowCount` pattern) for full determinism.
  - Net: every card has [fixed image] + [title 1-2 lines] + [summary exactly N lines] + [1 badge row] + [1 tech row] + [footer], so every row is the same height and the grid stays even.
- Effort: Low. Pure `resources/js/components/projects/project-idea-card.tsx` + a card test.

## Risks / Integration Concerns
1. **`Storage::fake` vs real disk in the seeder-copy test** — seeder reads the repo asset via `file_get_contents(database_path(...))` (real FS) and writes via `Storage::disk($disk)` (fake in tests). The existing `test_seeder_is_idempotent_and_covers_every_category` does NOT call `Storage::fake` today; adding a file-write side effect means that test must add `Storage::fake('public')` + `config(['filesystems.media_disk'=>'public'])` or it will write into `storage/app/public` during the suite. Deterministic dest path keeps `assertSame(15,...)` / pivot-count assertions valid.
2. **Seeder idempotency regression** — if `illustration_path` used a random/uuid dest, upsert would rewrite the column every run and the idempotency test's implicit "no change" expectation (and any future `updated_at` check) breaks. MUST be deterministic (`project-ideas/<slug>.webp`). Re-copy: either unconditional overwrite (cheap, still idempotent in content) or `exists()` skip. "Pick up newly-added images" requirement satisfied because a newly-present source file flips `illustration_path` from null on the next run.
3. **`idea_slug` staying set after the user edits fields away from the idea** — LOCKED behavior is "uploaded images always win; else idea illustration". If the user picks an idea (sets `idea_slug`), then rewrites title/description entirely but uploads no image, the created project still gets that idea's illustration as cover. **Assessed acceptable**: it is still a themed, on-topic cover and the user can change it later in edit. Document as intentional. Mitigation option (NOT taken, would re-litigate): clear `idea_slug` on manual title edit.
4. **`ConvertEmptyStringsToNull` + `forceFormData`** — `form.post(..., {forceFormData:true})` serializes `idea_slug:''` into multipart as `""`. Laravel's default `ConvertEmptyStringsToNull` middleware turns `""`→`null` so `nullable` short-circuits before `exists`. Confirm the middleware is active (Laravel 12 default) — if a project ever removed it, `exists:project_ideas,slug` would fail on `""`. Assumption logged.
5. **`isSafeImagePath` rejecting the copied cover** — copy destination is `projects/<uuid>.<ext>` → passes (`str_starts_with('projects/')`). The `project-ideas/` source path would NOT pass, but it is never handed to `deleteImages`. Safe. Do NOT store the raw `project-ideas/...` path as `images[0]`.
6. **Card layout shift from the media region** — mitigated by fixed `aspect-video`; see layout section. Collapsible is `defaultOpen={false}` so no CLS on initial page paint.
7. **`ProjectIdeaInspirationTest` needs an `illustrationUrl` assertion** — plus the transformer test. Low effort, but the delta-spec must call it out as a scenario.
8. **`create.test.tsx` prefill-keys assertion** — `expect(new Set(keys)).toEqual(new Set(['title','description','vision','techs']))` and `keys` "not contain images/repository_url/demo_url" will fail once `applyIdea` also `setData('idea_slug', ...)`. The spec must update this scenario to expect `idea_slug` in the set.
9. **`tsc` gate** — informational (`tsc-staged` continue-on-error) but `npm run build` is a hard gate. New `illustrationUrl` field, `LucideIcon` typed maps, and `idea_slug` in `useForm` generic must all typecheck. `ProjectForm`'s `useForm<ProjectFormData>` prop type does not include `idea_slug`; `create.tsx` already passes a wider inline object so this keeps working, but if strict, may need `ProjectFormData` updated or a local type.
10. **Repo bloat from committed images** — 15 × ~300KB webp ≈ 4.5MB worst case; the 1200x675 + webp + size cap in the spec mitigates. Recommend enforcing the cap in review, and starting with a subset (missing files degrade gracefully to gradient+icon).
11. **Tailwind version mismatch in docs** — README/preflight say v3; repo is v4 (`@theme inline`, `@plugin`, oklch, `.dark` class, `tailwindcss ^4.3.0`, no `tailwind.config.js`). Gradient utility class names used here (`bg-gradient-to-t`, `from-*`) still work. Flag so downstream phases don't add a v3 `tailwind.config.js` or `dark:` color overrides.
12. **`@base-ui/react` (not radix)** — `Collapsible` already uses `render=` prop; any new primitive follows base-ui API. No new primitive needed for this change (plain `<div>`+`<img>`+lucide inside `Card`).
13. **Missing-image categories in the grouped view** — if only some of a category's 3 ideas have images, cards in that group mix photo + gradient. Fixed-aspect block + consistent structure keeps the row even; visually acceptable and expected during rollout.
14. **`with('techs:id')` eager-load unaffected**; add nothing to the controller query except (optionally) nothing — `illustration_path` is a column on the base row, already loaded.

## Locked decisions that fight the codebase (minimal adjustments, do NOT stop)
- **Seeder dest path must be deterministic** (`project-ideas/<slug>.webp` on media disk), not uuid — otherwise upsert idempotency test regresses. Copy source is read from the repo tree via `file_get_contents(database_path(...))`, not `Storage`.
- **`create.test.tsx` and `project-idea-inspiration.test.tsx`/`ProjectIdeaInspirationTest` have assertions that will fail** the moment `idea_slug`/`illustrationUrl` land; the spec must enumerate those exact scenario updates (not new files only).
- **Theme-aware fade**: put the image in a fixed-aspect block ABOVE the card header (header keeps `bg-card`), so the fade only blends the image edge and never has to guarantee text contrast over arbitrary photography. Avoid `dark:` color classes; rely on `--background`/`--card` flipping.
- **Tailwind is v4** despite docs; no `tailwind.config.js` exists. Keep gradient classes, use semantic tokens.
- Everything else (nullable column, media disk + `StorageUrlHelper`, `idea_slug` validation, `images[0]` cover convention, English/Spanish split) matches existing conventions with no friction.
